# 多 Agent 协作销售分析系统

面向内部零售运营的销售分析平台，计划通过 POP 商品资料与每日商品销售汇总，提供商品目录、门店库存、销售分析、冷热商品分析，以及管理员专用的多 Agent 协作分析能力。

> 当前状态：**P0 计划与接口评审阶段**。业务数据库字段、建表 SQL 和模块接口尚未最终确认；仓库当前不是可运行成品，请勿据此部署生产环境。

## 当前工作原则

项目采用“计划确认 → 分模块接口评审 → 数据模型评审 → 后端接口与测试 → 对应前端页面 → 浏览器联调验收”的垂直切片方式开发。

- 在总体计划和字段模型确认前，不创建正式业务表或 Flyway 迁移。
- 总体计划定稿后，将 M01–M10 分别生成独立接口文档。
- 每个后端功能必须同步实现对应前端页面，并通过真实接口进行浏览器测试。
- 当前仓库中的前端文件仅为早期界面草案；后端工程已从未评审草案中移除。

## 已确认的核心业务规则

- 系统包含管理员和普通用户；普通用户唯一绑定一个门店。
- 普通用户可查看所属门店的条形码、供应商、商品名称、规格、单位、分类、售价、状态、最新已知库存及同步时间。
- 商品单位直接保存为文本，不建立单位字典；管理员可修改，普通用户只读。
- 商品分类全系统共享并支持最多 5 级父子层级，根分类计为第 1 级；商品资料带入商品类别，普通用户和管理员都可创建父级分类并调整类别归属。
- 商品只能关联没有子分类的叶子分类；已有商品的分类不能再增加子分类，人工父级主要用于组织分类目录。
- 管理员可以在商品编辑页将商品调整至其他启用的叶子分类，普通员工只能查看商品分类。
- 商品通过商品资料首次进入本系统时，使用该行 POP 商品类别初始化其分类；同一条码后续即使导入了不同品类，也继续使用系统中的当前分类，不被导入覆盖。
- 管理员可在商品页面手工调整已有商品分类；系统不保存“最近一次 POP 分类”，也不提供恢复 POP 分类操作。
- 系统内分类停用不级联停用或移动商品；已有商品继续显示原分类及停用标记，但该分类不能再用于新的商品归属。POP 源端不会停用分类，因此导入不处理“新商品命中已停用 POP 分类”的分支。
- 首次导入的新 POP 类别创建为根分类；人工归入父级后，后续商品资料导入不得重置该父级关系。
- 已存在的 POP 分类名称和父级关系不再被后续导入覆盖，分类结构与名称统一在系统页面维护。
- 普通员工可创建分类和调整父级，但分类重命名、启用或停用仅允许管理员操作。
- POP 类别以品类编码全局唯一匹配；人工父级只填写名称，不要求员工编写分类编码。
- 同一商品的当前售价按门店分别保存；普通用户只查看所属门店售价，管理员可查看并维护各门店售价。
- 管理员手工修改门店售价时无需填写日期，系统自动记录操作当天作为售价来源日期，并保留精确操作时间。
- 每日销售表中的“当前机构售价”对应目标门店；只有所选营业日期不早于现有售价来源日期时才覆盖本店当前售价，旧日期导入不回退售价。
- 普通用户可为所属门店导入每日销售汇总并查看本店导入批次，但不能查看销售金额、成本、利润、毛利率、其他门店库存或 AI 功能。
- 商品与供应商为多对多关系；供应商用于展示商品来源，不作为销售分析维度。
- 当前进价按“门店 + 商品 + 供应商”分别保存，每个组合只保留最新进价及来源日期；商品资料和每日销售汇总只更新目标门店，不能改动其他门店进价。系统不建设历次进价历史，历史销售成本仍以每日销售事实快照为准，普通用户不能查看进价。
- 商品资料中的毛利率不入库；历史毛利分析仅使用每日销售汇总中的销售毛利率快照。
- 每日销售表中的三列同期值不入库；同比和环比由系统历史销售事实计算，历史不足时显示暂无可比数据。
- 商品当前条码全局唯一，按 1–64 位数字或英文字母字符串保存并保留前导零；管理员可修改，普通用户不可修改。
- POP 中商品和库存数据完整，POP 库存是本系统唯一权威库存来源。
- 商品资料可以分多个批次逐步同步到本系统；每批只新增或更新出现的条码，批次外商品保持不变。
- 商品资料导入前由管理员必选资料日期，作为该批次进价、门店售价和库存的来源日期；旧资料不能回退较新的当前值。
- 已有商品采用非空覆盖：空单元格保留旧值，有效非空值才覆盖；空值不表示清空或写零。
- 系统只定义【商品资料】和【每日销售汇总】两种导入模板；两种模板中的有效库存、成本和售价均可刷新对应当前值，并按来源日期防止旧数据回退。
- 商品资料和每日销售文件中的有效库存值直接覆盖对应门店商品库存，不使用销量推算库存。
- 每日销售文件中“本期销售数量”为 0 的行整行舍弃，不创建销售事实，也不更新当前进价、门店售价或库存；负销量仍按退货事实处理。
- 每日销售导入前必须选择营业日期；销售事实长期保留，单次主查询区间最多连续 31 个自然日，同比和环比由后端自动读取历史对比区间。
- 多 Agent 分析仅管理员可用，Agent 只能调用预定义的聚合查询工具，不能执行自由 SQL。
- 业务审计日志仅管理员可查，用于追踪关键操作；它不保存密码、令牌、API Key 或完整 Excel 内容，供应商及报价变化不进入审计。

## 计划技术栈

- 后端：Java 17、Spring Boot 3.5.8、Spring AI Alibaba 1.1.2.2、Spring AI 1.1.2、MyBatis-Plus、Spring Security、Flyway、Apache POI。
- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus、ECharts、Axios。
- 数据与基础设施：MySQL、Redis、Elasticsearch；生产环境计划切换阿里云 RDS MySQL、Redis 和 Elasticsearch 服务。
- AI 模型：阿里云百炼 Qwen，通过 DashScope 接入。
