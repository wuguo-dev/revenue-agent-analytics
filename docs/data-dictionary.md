# 数据字典（初稿）

核心域：用户与角色、门店、供应商、分类、商品、门店商品最新已知库存、POP 库存快照、库存同步记录、仓库货位、商品货位、导入模板、导入批次、每日销售事实、评分配置、Agent 会话与运行记录。

## 用户与角色

- 首版固定 `ADMIN`、`USER` 两种角色，不提供动态角色或权限配置。
- 管理员不绑定门店，可创建管理员和普通用户账户；普通用户必须且只能绑定一个启用门店，一个门店可以绑定多个普通用户。
- 普通用户的数据范围只取服务端账号门店绑定，不能由客户端提交的 `storeId` 替代。
- 用户不设置启用/停用状态：未删除且绑定规则有效的账户即可登录。
- 管理员可以删除普通用户，也可以注销自己或其他管理员，但系统必须始终保留至少一个管理员账户。
- 账户删除或注销后立即失去登录能力、全部会话失效且不可恢复；内部保留最小历史身份，原用户名永久保留，历史业务记录不迁移也不失去操作人归属。
- 管理员与普通用户可以互转角色；转为普通用户时必须绑定启用门店，转为管理员时清空门店绑定。角色变化或门店改绑使全部旧会话失效。
- 用户名去除首尾空白后转为小写，按 4～32 位、字母开头以及字母/数字/点/下划线/连字符校验；创建后不可修改，账户删除或注销后也不可复用。
- 个人资料包含姓名 `displayName`、性别 `gender`、手工年龄 `age` 和入职日期 `hireDate`。管理员和普通用户均可修改本人资料，管理员还可修改其他未删除账户；本人资料接口不能修改用户名、角色、门店或密码。
- `gender` 固定为 `MALE/FEMALE/UNSPECIFIED`；`age` 为 16～100 的可选整数，由用户手工维护，不保存出生日期、不自动增长；`hireDate` 不晚于当天。
- 密码只由管理员在创建账户或重置时设置；员工无自助改密和找回密码能力。管理员重置任一账户密码后，目标账户全部已有会话失效。

## 认证与会话

- 账号由管理员统一创建并分发；员工没有修改密码权限，只有管理员可以创建或重置密码。
- 密码采用 bcrypt 单向哈希，首版接受 8～32 位半角字符，不强制字符组合，也不周期性要求修改。
- 登录采用 Redis 服务端会话和不透明随机会话 ID；浏览器只通过 `HttpOnly`、生产环境 `Secure`、`SameSite=Lax` 的 `SA_SESSION` Cookie 携带认证凭据，不把认证凭据写入 Web Storage，也不签发前端可读 JWT。
- 会话空闲有效期 30 分钟并滑动续期，绝对有效期 12 小时；同一账号最多保留 3 个会话，第 4 次登录撤销最早会话。
- 管理员重置密码、删除或注销账户、修改角色或门店绑定时，目标账号全部旧会话立即失效；Redis 不可用时受保护请求安全失败。

## 门店生命周期

- 门店以不可变内部 `id` 作为业务引用；展示使用门店编码和名称。编码去除首尾空白后转为大写，按 `[A-Z][A-Z0-9-]{1,31}` 校验，在现存门店中全局唯一且创建后不可修改；空门店物理删除后编码可以复用，但新门店必须取得新的内部 `id`。
- 门店名称去除首尾空白后为 1～100 个字符，允许重名且不作为唯一匹配条件。地址可选、最多 255 个字符；联系人可选、最多 50 个字符；联系电话可选、最多 30 个字符，按字符串保存并拒绝控制字符。可选文本全为空白时统一保存为 `null`。
- 门店状态固定为 `ACTIVE/DISABLED`。停用门店不再用于新账号绑定、账号改绑或新业务操作，已有历史数据仍保留原门店引用并可由管理员查询。
- 门店存在尚未删除的普通用户绑定时不能停用，必须先改绑或删除这些用户；停用操作不自动处理账号。
- 门店支持物理删除，但仅限已经停用、没有未删除用户绑定且没有任何主数据或业务数据引用的空门店。
- 门店存在商品、供应商关系、售价、库存、导入批次、库存快照/同步/告警、销售事实、分析配置或其他业务记录时，只能保持停用；禁止通过删除门店级联清理、迁移或改写这些数据。
- 物理删除在同一事务中复核门店状态与所有引用；并发产生新引用时删除失败。审计保存门店 ID、编码、名称及删除结果快照，不以外键反向阻止符合条件的删除。

## 用户与门店接口并发

- 用户与门店列表统一返回 `PageResult<T> { items, page, size, total }`；`page` 从 1 开始，`size` 默认 20、最大 100，无结果时返回空列表。
- 创建返回 201 和完整视图，更新返回 200 和最新视图，账户/门店删除及密码重置返回 204。新建门店固定为 `ACTIVE`，不能在创建请求中指定状态。
- PUT 写操作在请求体携带 `expectedVersion`，账户与门店 DELETE 使用 `If-Match`；版本缺失或不一致返回 409，原数据不变。
- 已成功删除请求的网络重试可依据删除记录幂等返回 204 且不重复审计；从未存在的 ID 返回 404。

## 用户与门店权限及审计

- M02 是账号、固定角色、门店和账号门店绑定的权威来源；普通用户门店范围及本人资料目标只取当前认证主体，客户端提交的角色、门店或其他用户 ID 不能覆盖。
- `/admin/**` 仅管理员可访问；前端隐藏入口不替代后端授权。门店物理删除需要通过跨模块引用探针汇总业务引用，任一检查不可用或不完整时安全失败。
- 账户创建/删除/注销、角色与门店改绑、密码重置，以及门店创建、编辑、启停和删除均发送脱敏审计事件；最后管理员、门店有关联用户或业务引用等重要拒绝也记录，普通字段格式错误不逐条写业务审计。
- 明文密码、密码哈希、会话标识、Redis 会话值、完整请求体及客户端伪造的服务端内部字段不得进入响应、日志或审计。所有状态变更继续执行 M01 的 CSRF Token 与 Origin 校验。

## 商品公开字段

条形码、供应商、商品名称、规格、单位、分类、所属门店当前售价、状态，以及当前用户所属门店的最新已知库存和最后同步时间。普通用户响应不包含其他门店售价。

## 管理员字段

在公开字段基础上包含各门店当前售价、按“门店 + 商品 + 供应商”拆分的当前进价、各门店最新已知库存、库存最后同步时间、销售数量、销售金额、成本、利润和毛利率。

## 商品单位

- 商品单位直接保存为自由文本，例如“个”“瓶”“盒”“袋”，不关联单位字典，也不建设独立的单位管理功能。
- 管理员可在商品维护接口和页面修改单位；普通用户只能在商品目录查看。
- 商品资料导入时，已有商品的非空单位覆盖旧值，空单元格按通用非空覆盖规则保留旧值。

## 商品分类

- 商品分类是全系统共享的多级父子层级，不按门店隔离；根分类没有父级且计为第 1 级，最大为第 5 级。
- 商品通过商品资料首次进入本系统时，以表内 POP 商品类别初始化商品分类；普通用户和管理员均可创建父级分类，并调整已有类别的父级归属。
- 商品只能直接关联没有子分类的叶子分类；分类不能同时直接关联商品并拥有子分类。商品资料匹配到已有子分类的 POP 类别时，预检报错并阻断整批提交。
- 商品只保存一个当前有效分类 `categoryId`，不保存最近一次 POP 分类或商品分类来源状态，也不提供恢复 POP 分类能力。
- 已有商品后续无论导入商品资料还是每日销售汇总，都不得修改其 `categoryId`；管理员可以在页面把商品调整至其他启用的叶子分类，普通用户只读，手工调整记录新旧分类并触发商品搜索索引同步。
- 管理员停用系统分类时不级联修改已关联商品；商品继续保留分类并显示停用状态，商品自身状态不变。停用分类不得用于新的商品创建或手工分类调整。POP 源端不会停用分类，导入不接收分类状态，也不设计“新商品命中已停用 POP 分类”的阻断或自动处理分支。
- 分类调整父级时必须阻止指向自身或后代，避免形成循环；创建或移动后的整个子树不得超过第 5 级，目标父分类不得已有直接关联商品。关联商品的分类不物理删除，通过状态停用。
- 普通用户可创建分类和调整父级，但不能重命名、启用或停用分类；重命名和状态维护仅管理员可执行。
- POP 来源类别保存品类编码，该编码在全系统唯一并作为导入匹配键，不允许通过分类维护页面修改。
- 人工父级分类不保存业务编码，创建时只填写名称，由系统内部 ID 标识并参与父子关系。
- POP 商品资料只有品类编码和品类名称，不能表达父级链路或停用状态；导入不得根据名称猜测层级。系统中首次出现的 POP 商品类别创建为根分类；已有类别按品类编码匹配，后续导入不得覆盖其名称、状态或父级关系。同一条码后续导入不同品类时仍保留系统当前 `categoryId`，以首次导入形成的分类为基准；管理员可在系统内修改商品分类，且该修改同样不被后续导入覆盖。

## 供应商进价口径

- 每个门店商品只保留一个当前供应商；当前进价随“门店 + 商品 + 当前供应商”组合保存，只保留最新进价和进价来源日期，不建设历次进价历史。`StoreProductSupplier` 除组合唯一性外还必须约束“门店 + 商品”最多一条当前记录。
- 商品资料中的含税成本价和每日销售中的当前机构最后进价只更新目标门店对应的商品供应商组合；不比较资料日期或营业日期，最后成功提交的 POP 批次覆盖当前进价，且不能影响其他门店。来源日期只用于追溯；每日销售中的进价还要同时保存为历史销售成本快照。
- 供应商及门店商品供应来源不设置启用/停用状态，不提供人工新增、修改、删除关系或人工改价能力。POP 导入无需预建关系；相同条形码出现非空新供应商时，用新供应商替换该门店商品的旧供应商并只保留新记录。同一文件内供应商不同的重复条码按 Excel 原始行号最后一行胜出；商品未出现或供应商为空时保留当前供应商。
- 普通用户查看所属门店商品的当前供应商名称，但不能查看进价；管理员可查看各门店当前供应商名称和当前进价。供应商及报价变化不进入业务审计。

## 售价口径

- 当前售价属于“门店 + 商品”关系，同一条码在不同门店可以不同，不在全局商品主档保存唯一售价。
- 普通用户只读取账号所属门店当前售价；管理员可查看各门店当前售价，但当前售价只能由 POP 导入更新，不提供人工维护。
- 每个门店商品当前售价同时保存 POP 来源日期和来源批次用于追溯，但二者不作为覆盖优先级依据。
- 商品资料导入前由管理员必选资料日期，代表 POP 导出数据日期；商品资料成功提交后直接更新所选门店售价。
- 每日销售表中的“当前机构”就是目标门店；“当前机构售价”保存为销售快照，并在批次成功提交后覆盖目标门店当前售价，即使营业日期早于当前记录的来源日期。
- 同一批次同条码出现多个非空售价时按 Excel 原始行号取最后一个；跨批次以后成功提交者胜出。

## 库存口径

- POP 是唯一权威库存来源，本系统不使用销量计算库存。
- POP 中商品和库存数据完整，商品资料可导出单门店全部商品并包含零库存、已停用商品；新系统允许分批同步，每批只覆盖出现商品的门店库存。“尚未同步”不表示 POP 缺少该商品或尚未完成实体入库。
- 每日销售汇总只覆盖文件中出现商品的库存；缺失商品保持原值。
- 当前库存必须附带来源批次、来源营业日期和最后同步时间。
- 当前库存按“门店 + 商品”唯一；库存快照按“来源批次 + 门店 + 商品”唯一且不可变；同步记录按“一个已提交导入批次一条”保存摘要。
- 新鲜度按最近成功应用当前库存投影的 `lastSyncedAt` 及 `Asia/Shanghai` 自然日计算；默认阈值 3 天，严格超过 3 天为陈旧。来源日期不影响是否应用，任何后续成功 POP 批次都会刷新新鲜度。
- 负库存提交时即时产生站内告警；陈旧库存每天凌晨 04:00 扫描。管理员只能确认知悉，异常消失后系统自动恢复。
- 总库只汇总已知库存；未知门店不按零参与，必须同时返回覆盖完整度。
- 库存差异仅表示两次 POP 观察值之差，不解释为销售、进货或盘点流水。

## 商品资料合并口径

- 商品资料按条码 upsert；已有条码只用校验通过的非空值覆盖对应字段。
- 商品资料批次保存管理员选择的资料日期；该日期作为批次中进价、门店售价和库存的追溯字段，不能用上传或提交日期替代，但不参与覆盖优先级判断。
- 条码是 1 至 64 位数字或英文字母组成的字符串，保留前导零，是可由管理员受控修改的当前业务唯一标识，不作为数据库主键；普通用户不能修改。修改条码时内部商品 ID 及其历史销售、库存和关系数据保持不变；不保存可参与匹配的旧条码别名，导入只匹配当前条码。
- 已有条码的空单元格表示“不更新”，保留系统旧值，不表示清空或写零。
- 新商品缺少必填字段，以及任意非空字段格式错误，均为错误行并阻断整批提交。
- 供应商字段为空时保留目标门店现有商品供应商记录，不删除关系；有进价但供应商名称为空时必须报错，不能退化为商品级或门店商品级进价。新的非空供应商名称无需预先建档，由 POP 导入直接写入对应记录。

POP 两类 Excel 的最终表头别名在取得脱敏样表后补充；系统通过可保存的映射模板解耦列顺序和表头差异。

## 销售历史与查询窗口

- 每日销售事实长期保留，首版不自动删除，也不只保存最近一个月。
- 用户选择的主查询区间最多连续 31 个自然日，开始日期和结束日期都计入范围。
- 同比、环比由后端基于主查询区间自动读取等长历史区间，不要求用户另行扩大查询窗口。
- 同比固定使用主查询区间向前推一个自然年的对应日期区间；环比固定使用紧邻主查询区间之前、包含相同自然日数量的连续区间。

## 零销量行

- 每日销售源行的“本期销售数量”等于 0 时整行舍弃，不创建或修正每日销售事实，也不更新门店供应商当前进价、门店当前售价或最新已知库存。
- 销售收入是否为 0 不改变该规则；过滤在同条码聚合之前执行。
- 负销量不属于零销量行，仍保留为退货事实，但不使用销量加减库存。
- POP 每日销售表中的同期销售收入、同期销售数量和同期销售毛利率全部舍弃，不落库、不参与计算，也不在历史不足时补值。
- 历史不足时比较结果标记为不可用，增长率返回空值，页面显示“暂无可比数据”，不能显示为 0%。
- 31 日限制约束单次交互和分析范围，不是数据生命周期；原始导入文件、审计日志的保留期限另行确认。

## 毛利率口径

- 商品资料中的毛利率舍弃，不进入商品主档、门店商品或门店商品供应商关系，也不作为商品导入目标字段。
- 每日销售表中的销售毛利率按门店、营业日期、商品保存为销售事实快照，管理员经营分析使用该快照。
- 商品售价或门店供应商当前进价后续发生变化时，不回写历史销售毛利率；普通用户不能查看销售毛利率。

## 业务审计日志

- 审计日志记录关键业务操作的操作人、发生时间、模块、动作、目标对象、所属门店、执行结果、请求追踪号和必要变更摘要，仅管理员可查询。
- 它不等于销售事实、库存快照或应用运行日志；程序异常和错误堆栈进入应用日志。
- 不保存密码、密码哈希、Cookie、会话标识、CSRF token、Redis 会话值、API Key、数据库凭据、完整请求体或完整 Excel 行内容。
- 首版不提供审计记录修改和删除接口；供应商及其报价变化按业务约定不进入审计。审计日志具体保留期限在上线门禁 G5 确认。
