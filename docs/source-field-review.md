# POP 源表字段评审（DRAFT）

> 数据来源：`商品资料1.xls`、`商品销售汇总.xls`。本文档确认前不创建数据库表。

## 1. 已确认业务规则

- 条形码是商品当前唯一业务标识，按 1 至 64 位数字或英文字母字符串处理并保留前导零；管理员可通过商品编辑功能受控修改，普通用户不可修改。修改后内部商品 ID 和历史关系保持不变，旧条码不保留为匹配别名，商品资料导入本身不承担条码修改。
- 商品与供应商是多对多关系。同一商品可在不同日期由不同供应商供货，采购价格可以不同。
- 供应商用于展示商品来源，不做供应商销量、销售额或毛利分析。
- 每日销售事实来自每日商品销售汇总，系统按门店、营业日期、条形码保存。
- 管理员和普通用户都可以导入每日销售汇总；营业日期在导入页面中必选，整份文件归属所选日期。
- 普通用户只能为账号绑定门店导入，不能通过请求参数切换门店。
- 普通用户可以查看账号所属门店全部用户创建的销售导入批次，但不能查看其他门店批次。
- 同一销售文件中同条码的多供应商行按条码合并后同步库存，避免重复使用库存快照。
- POP 是唯一库存来源；销售汇总只包含当日销售商品，因此每次导入只覆盖文件中出现商品的门店库存，未出现商品保持原值。
- POP 中的商品和库存数据完整，商品资料可覆盖单一门店全部商品并包含零库存和已停用商品；新系统允许将资料拆成多份、分批同步。所谓“新增商品”只指尚未进入本系统的 POP 商品；新系统中不存在的条码新增商品主档和门店关系，已有条码更新资料并覆盖库存，不代表采购或实体入库，也不做进货累加。
- 商品资料已有条码采用非空覆盖：空单元格保留系统旧值，不清空字段；有效非空值才覆盖。新商品必填字段为空或非空值格式错误时仍作为错误行阻断整批。
- 普通用户可以在商品资料页面查看所属门店最新已知库存和最后同步时间，但不能查看其他门店库存。
- 同一条码的当前售价按门店分别保存；普通用户只查看所属门店售价，管理员可查看和维护各门店售价。
- 每日销售表中的“当前机构”指本次导入选择或账号绑定的目标门店；其“当前机构售价”在保存当日快照的同时更新该店当前售价，但只有营业日期不早于现有售价来源日期时才允许覆盖。
- 商品资料导入前由管理员必选资料日期，代表 POP 导出数据日期；该日期作为文件中进价、门店售价和库存的来源日期，旧资料不得回退较新的当前值。
- 管理员手工修改门店售价时不填写日期；系统自动以操作当天作为售价来源日期，并另行记录精确操作时间。
- 当前进价按“门店 + 商品 + 供应商”保存，每个组合只保留最新进价及来源日期，不建设历次进价历史；商品资料以资料日期、每日销售表以营业日期只更新目标门店对应组合，旧日期不得回退且不能影响其他门店。每日销售成本同时保存为历史销售成本快照。普通用户不能查看进价，供应商及报价变化不进入审计日志。
- 商品资料中的“毛利率”舍弃，不进入任何商品核心数据或导入目标字段；历史毛利分析只使用每日销售表中的“销售毛利率”快照。
- 每日销售表中的同期销售收入、同期销售数量和同期销售毛利率全部舍弃；同比和环比统一从系统长期保存的销售事实计算，历史不足时显示暂无可比数据。
- 每日销售事实长期保留且首版不自动删除；用户单次选择的主查询区间最多连续 31 个自然日，同比和环比由后端自动读取对应历史区间。
- 每日销售表中“本期销售数量”为 0 的行整行舍弃，不创建销售事实，也不更新当前进价、门店售价或库存；即使销售收入非 0 也同样舍弃。负销量仍作为退货事实。
- 首版只有【商品资料】和【每日销售汇总】两种导入模板；两种模板都允许从有效源列更新当前进价、门店售价和门店最新已知库存。
- 商品通过【商品资料】首次进入本系统时，使用 POP 类别初始化商品分类；POP 源端不会停用分类。同一条码后续通过任一模板导入时，即使品类不同，也保留系统中的当前商品分类，不由导入覆盖；管理员可以在系统页面修改商品分类。

## 2. 商品资料字段建议

| POP 字段 | 建议 | 系统用途 | 说明/待确认 |
|---|---|---|---|
| 商品名称 | 保留 | 商品主档名称 | 必填 |
| 条码 | 保留 | 商品当前唯一业务键 | 1–64 位数字或英文字母，文本存储并保留前导 0，必填；仅管理员可在商品编辑页修改，导入不用于改码 |
| 单位 | 保留 | 商品单位 | 自由文本，不建立单位字典；管理员可修改，普通用户只读；已有商品按非空覆盖 |
| 供应商名称 | 转换保留 | 供应商及门店商品供应商关系 | 同一商品在同一或不同门店均可对应多个供应商 |
| 含税成本价 | 转换保留 | 目标门店商品供应商当前进价 | 每个门店 + 商品 + 供应商只保留最新值及资料日期，不建设历次进价历史；不作为商品全局或跨门店统一成本 |
| 售价 | 转换保留 | 所选门店商品当前售价 | 同一商品允许各门店售价不同；不写入全局商品主档 |
| 毛利率 | 舍弃 | 预检忽略列 | 多供应商、多进价下商品层单一毛利率易失真；不入库、不参与计算 |
| 品类编码 | 保留 | POP 类别全局唯一匹配键 | 文本存储并保留前导 0；首次出现的类别创建为根分类，页面不可修改 |
| 品类名称 | 首次初始化保留 | 新商品初始分类名称 | 仅条码首次进入本系统且 POP 分类编码尚不存在时创建分类；后续导入不覆盖已有分类名称或商品归属 |
| 库存数量 | 保留并覆盖 | 首次同步及后续刷新门店商品最新已知库存 | 有有效数值时直接覆盖，不做累加；已有条码该单元格为空时保留旧库存，新商品为空时阻断 |
| 商品备注 | 保留 | 商品说明 | 可空 |
| 提成率/固定值 | 建议舍弃 | 当前系统无员工提成业务 | 若未来需要提成模块再单独设计 |

## 3. 每日商品销售汇总字段建议

| POP 字段 | 建议 | 系统用途 | 说明/待确认 |
|---|---|---|---|
| 条码 | 保留 | 关联商品、销售聚合和定位待覆盖库存 | 必填；同文件重复条码先聚合 |
| 商品名称 | 仅校验 | 与系统商品名称比对 | 核心销售表只保存商品 ID，不重复保存名称 |
| 本期\|销售数量 | 保留并过滤 | 非零值作为当日净销售数量 | 等于 0 时整行舍弃；负数作为退货事实，但不加减库存 |
| 选中机构库存数量 | 保留并覆盖 | 直接覆盖该门店商品最新已知库存 | `当前机构库存数量` 作为表头别名；未出现商品不变 |
| 当前机构最后进价 | 保留快照并按时序更新 | 当日 POP 成本快照；符合时序时更新目标门店商品供应商当前进价 | 按门店 + 商品 + 供应商定位；营业日期不早于该组合现有进价来源日期才覆盖，不影响其他门店；不建设进价历史 |
| 当前机构售价 | 保留快照并按时序更新 | 当日 POP 售价快照；符合时序时更新目标门店当前售价 | 当前机构即目标门店；营业日期不早于现有售价来源日期才覆盖；不能反算收入 |
| 销售毛利率 | 保留快照 | 当日销售毛利分析 | POP 原值可能不是由最后进价直接计算，不能自行覆盖 |
| 本期\|销售收入 | 保留 | 当日实际销售收入 | 权威金额字段 |
| 销售占比 | 舍弃 | 查询时按收入/总收入计算 | 明细合计约 100%，属于派生值 |
| 日均销售 | 舍弃 | 按查询周期动态计算 | 样表所有行均为 0 |
| 同期\|销售收入 | 舍弃 | 系统历史事实计算同比/环比 | 不导入；历史不足时不使用 POP 值补齐 |
| 同期\|销售毛利率 | 舍弃 | 系统历史事实计算同比/环比 | 不导入；历史不足时不使用 POP 值补齐 |
| 同期\|销售数量 | 舍弃 | 系统历史事实计算同比/环比 | 不导入；历史不足时不使用 POP 值补齐 |
| 品类名称 | 仅校验 | 验证商品品类或发现主档差异 | 销售事实通过商品关联品类 |
| 供应商名称 | 转换保留 | 定位目标门店商品供应商当前进价 | 不写入销售事实或作为销售分析维度；当前机构最后进价有值时必须可识别供应商 |

## 4. 样表数据质量发现

- 商品资料样表只有 1 条数据，足以确认格式，不能用于判断实际空值率和重复率。
- 销售表有 899 条商品明细和 1 条合计行；导入必须识别并排除合计行。
- 销售表有 892 个唯一条码、7 个重复条码组；重复组均由供应商不同造成。
- 有 413 条本期销量为 0，按已确认规则整行舍弃；1 条销量为负数，仍作为退货事实处理。
- 有 20 条 POP 库存为负数，可用于数据质量告警。
- 68 条销售收入不等于销售数量乘当前售价，说明存在优惠、改价或成交价差。
- 销售占比合计约 100%，可动态计算；日均销售整列为 0，不应存储。
- 销售文件没有营业日期字段，营业日期由导入页面选择，不从文件名或表内字段推断。

## 5. 当前状态

两类样表的首轮字段取舍已完成确认；数量与金额精度、退货统计公式等实现口径继续在阶段门禁 G1/G4 逐项确认。

业务方确认不会出现整份每日销售文件在零销量过滤后没有任何非零销量数据的情况，首版无需为该情形增加专用处理。

系统分类为全系统共享的多级父子层级。商品通过商品资料首次进入本系统时带入 POP 商品类别，首次出现的类别创建为根分类；普通用户和管理员均可创建父级并调整类别归属。

人工创建的父级分类只填写名称，不使用 POP 品类编码，由系统内部 ID 标识。分类树最多 5 级，根分类计为第 1 级，创建或移动不得使任何子孙超过第 5 级。商品只能关联叶子分类；已有商品的分类不能增加或移入子分类，新商品资料匹配到非叶子 POP 类别时预检阻断。管理员可在商品页面手工修改商品分类，普通用户只读；系统只保存当前分类，不保存最近 POP 分类或恢复状态。已有商品后续通过商品资料或每日销售汇总导入时，文件类别不覆盖当前商品分类；已有 POP 分类名称、状态和父级也不由导入覆盖。

管理员可以停用已有商品关联的系统分类，商品自身状态和归属不变，页面显示分类停用标记；停用分类不能用于新的商品归属。POP 源端不会停用分类，因此首次导入不设计停用 POP 分类的阻断或自动处理分支；同一条码后续即使携带不同品类，也继续使用系统当前分类，管理员可在系统中修改该分类。
