# POP 权威库存业务方案

> 状态：ACCEPTED。业务规则已确认；本文是正式实施计划和接口契约的库存设计依据。

## 1. 结论

可以废弃“初始化库存 − 每日销售数量”的库存计算逻辑，并建议首版采用该调整：**POP 是门店当前库存的唯一权威来源，本系统只同步、保存和展示 POP 库存，不根据销售数量自行推算当前库存。**

原因是当前系统并不掌握采购入库、盘点、报损、调拨、赠品、后台修正等全部库存事件。只扣销售数量得到的是“理论库存”，长期一定会与 POP 实际库存产生偏差。继续同时维护两套可写库存，还会出现哪个数值才可信的问题。

这不等于直接无条件覆盖数据库。正确做法是“校验后的库存快照同步”：保存每次 POP 快照、来源批次和同步时间，再用最新有效快照更新当前库存视图。

## 2. 统一业务术语

| 术语 | 含义 |
|---|---|
| 销售事实 | 某门店、某营业日期、某商品的销量、销售收入、成本和毛利快照 |
| POP 部分库存快照 | 每日销售文件中出现的商品及其 POP 实际库存集合 |
| POP 商品资料导出集 | POP 可为单一门店导出的全部商品及其最新库存，包含零库存和已停用商品 |
| 商品资料导入批次 | 实际提交到系统的一部分或全部商品资料，只覆盖批次中出现的条码 |
| 尚未同步到本系统的商品 | 已经存在于完整 POP 商品资料中，但尚未通过任何批次进入本系统的商品 |
| 最新已知库存 | 某门店、某商品最后一次从 POP 商品资料表或每日销售表取得的库存数量 |
| 库存同步差异 | 本次 POP 数量减去系统上次同步数量，仅用于记录变化和告警，不解释为销售、进货或盘点 |
| 营业日期 | 销售事实所属日期，由导入页面选择 |
| 资料日期 | POP 商品资料代表的数据日期，由管理员在导入前选择 |
| 库存快照时间 | 库存数值代表的观察时间，不能与营业日期混为同一个字段 |

页面不应把该数值称为“实时库存”，统一显示为“最新已知库存”，同时展示“最后同步时间”。Excel 导入只能提供批次观察值，不是真正的实时接口。

## 3. 推荐业务方案

### 3.1 库存职责

- POP 负责计算和维护实际库存；本系统通过商品资料表和每日销售表两个入口取得库存。
- 本系统不提供进货累加、销售扣减、退货回补、盘点调整等库存计算。
- 本系统负责导入前校验、保存库存快照、更新当前库存、记录同步差异、产生异常告警和提供汇总查询。
- 总库库存是各门店、各商品“最新已知库存”的求和结果，不保存第二份可编辑总库存；必须同时提示数据新鲜度。
- 销售数据和库存数据相互关联但职责独立：销售修正版只修正销售事实，不再反向加减库存。

### 3.2 商品资料分批同步与周期刷新

管理员在商品资料导入前必须选择资料日期，代表该文件的 POP 导出数据日期，不使用上传时间或提交时间代替。商品资料导入分成两个逻辑结果，在同一批次内原子提交：

1. 按条形码建立或更新商品档案。
2. 将商品表的“库存数量”作为该门店 POP 库存快照，并以资料日期作为库存来源日期。

POP 中的商品及库存数据已经完整，其可导出范围包含该门店全部商品、零库存商品和已停用商品；只是新系统不要求一次全部同步。管理员可以将资料拆分成多份、分多个批次提交；新系统中尚无的条码创建商品主档和门店商品关系，已有条码更新资料并覆盖库存，未出现商品保持原值。这里的“新增”只表示新增到本系统，不表示商品尚未进入 POP、尚未采购或尚未完成实体入库。该操作始终是 POP 数值覆盖，不是进货累加，也不建立持续扣减销量的库存余额。

已有条码采用非空覆盖：商品资料中的空单元格保留系统旧值，不用于清空字段；非空且校验通过的值才覆盖。新商品的必填字段为空，或任意非空字段格式错误，仍会导致预检失败。库存数量为空时也保留旧库存，并在预检摘要中标记为未更新，而不是写入空值或零。

商品资料中的有效库存由最后成功提交的 POP 批次覆盖门店最新已知库存，不比较资料日期。同一批次同条码存在多个非空库存值时取 Excel 原始行号最后一个；资料日期继续保存在批次和快照中用于追溯。

### 3.3 每日销售汇总导入

1. 用户选择营业日期；管理员选择门店，普通用户固定为账号所属门店。
2. 上传 POP 每日商品销售汇总。
3. 系统识别并排除合计行，再将“本期销售数量 = 0”的源行整行舍弃；零销量行不写销售，也不更新当前进价、售价或库存。
4. 对剩余非零销量行按条形码聚合重复供应商行。
5. 同条码多行的“选中机构库存数量”存在多个非空值时，按 Excel 原始行号取最后一个非空值并给出预览提示，不阻断整批。
6. 销量、收入、成本和毛利写入销售事实；“选中机构库存数量”写入库存快照。
7. 对过滤后仍出现的商品直接覆盖门店最新已知库存；文件未出现或仅出现在零销量行中的商品保持原值。
8. 记录更新前数量、POP 数量、差额、来源批次和同步时间；负库存允许保存，但生成告警。
9. 销售事实、库存快照、当前库存投影和批次状态在同一事务内提交，任一步失败整批回滚。

### 3.4 部分快照与缺失商品

- 已确认每日销售汇总只包含门店当日销售商品，因此每次导入都是部分库存快照。
- 文件中出现的商品按 POP 数量直接覆盖；文件中未出现的商品保持上一次已知库存，绝不自动置零。
- 销量为 0 的行按业务规则整行舍弃，即使条码、售价和库存有效也不执行同步；不能借助零销量行刷新库存。
- 未销售商品可能长期不更新，商品页和库存汇总必须显示最后同步日期，并支持筛选或告警“超过阈值未同步”的商品。
- 新鲜度默认阈值为 3 个自然日；系统每天凌晨 04:00（Asia/Shanghai）扫描陈旧库存并生成站内告警。任何日期的后续成功 POP 批次都会刷新当前库存和新鲜度。
- 周期性重新导入最新商品资料表可以刷新这些未销售商品，降低部分快照造成的陈旧风险。

### 3.5 修正版与乱序导入

- 同一门店、营业日期、条码再次导入时，按现有规则覆盖销售事实。
- 覆盖销售事实时不再计算销量差额并调整库存。
- 每个成功提交的销售批次都以文件中的 POP 库存覆盖当前库存，不比较营业日期；同批多值取 Excel 最后一条非空值，跨批次以后提交成功者胜出。
- 补录较旧营业日期时，销售事实按业务日期新增或修正，同时该批 POP 库存仍覆盖当前库存；营业日期只用于追溯。
- 系统同时保存来源营业日期和导入提交时间：前者用于业务追溯，后者用于确定当前值覆盖顺序和衡量数据新鲜度。

## 4. 方案对比

| 方案 | 准确性 | 复杂度 | 可解释性 | 建议 |
|---|---|---|---|---|
| 原方案：初始化库存持续扣减销售 | 缺少进货、盘点等事件时会持续漂移 | 中 | 能解释销售造成的变化，但无法解释其他变化 | 不采用 |
| 双库存：理论库存与 POP 库存并存 | 可做差异分析，但容易让用户混淆 | 高 | 最完整，需要维护两套口径 | 首版不采用 |
| 推荐：POP 部分快照为唯一库存来源 | 未销售商品可能陈旧 | 低至中 | 来源清楚，当前值可追溯到批次 | 已采用 |

可以在不维护第二套库存的前提下保留“同步差异”。例如上次 POP 库存为 10，本次为 7，系统记录差额 -3，但不武断地把 -3 解释成销售，因为其中也可能包含报损、盘点或调拨。

## 5. 优点

- 库存口径与实际使用的 POP 系统一致，避免双系统数值冲突。
- 不需要补建采购、报损、盘点和调拨模块就能获得与 POP 同口径的最新已知库存。
- 销售修正版逻辑明显简化，不会重复扣库存或错误回补库存。
- 每次库存都能追溯到门店、文件、批次、操作人和同步时间。
- 后续如果接入 POP API，可保持相同的“外部库存快照”模型，只更换同步渠道。

## 6. 缺点

- 库存新鲜度取决于 POP 商品资料表和每日销售表的导出、导入频率。
- POP 没有导出或导入失败时，本系统库存会停留在上次同步值。
- 仅凭快照差额无法解释库存变化的业务原因。
- 无法独立校验 POP 自身是否算错，只能做格式、范围、重复值提示和来源追溯。
- 如果不保存每次快照，只保留当前值，将无法进行历史库存趋势和问题追溯。

## 7. 主要风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 每日文件只含销售商品 | 未销售商品库存长期不更新 | 定期重新导入最新商品资料表；展示最后同步时间和陈旧告警 |
| 分批同步尚未覆盖全部 POP 商品 | 新系统同步阶段的商品和库存不完整 | 批次中心展示累计同步数量；尚未同步商品在 POP 中仍然完整有效，本系统不据批次缺失做业务判断 |
| 导入旧文件 | 较旧业务日期的数据成为当前值 | 页面明确提示“按提交顺序覆盖”；资料/营业日期仅用于追溯，用户确认后提交 |
| 营业日期与库存时间混淆 | 补录历史销售时覆盖今天库存 | 分离 `businessDate` 与 `inventorySnapshotAt` |
| 同条码多供应商重复行 | 同一库存被重复累计或取值含糊 | 条码聚合，按 Excel 原始行号取最后一个非空库存值并提示，不阻断整批 |
| POP 负库存 | 看板出现负数 | 接受真实值并产生负库存告警，不擅自改为零 |
| 普通用户误导入其他门店 | 污染门店库存 | 普通用户门店由后端绑定，禁止客户端指定 |
| 普通用户上传错误文件 | 销售与库存同时被错误更新 | 预检、确认提交、批次追踪、文件指纹和整批事务 |
| 重复或修正版导入 | 库存被二次扣减 | 完全取消销售扣库存；销售事实按业务键修正，库存由后成功提交批次直接覆盖 |
| 普通用户访问其他门店库存 | 造成门店数据越权 | 商品目录和导入接口均由后端绑定所属门店；普通用户可以看本店库存但不能切换门店 |
| 同一门店并发提交 | 完成顺序不明确 | 门店级提交串行化，按事务成功提交顺序确定最终值 |

## 8. 对现有计划的影响

因方案已确认，正式计划需要修改以下内容：

- 使用可重复执行的【商品资料】导入：先将 POP 商品和库存逐批同步到新系统，后续用最新商品资料刷新库存；不再拆分 `PRODUCT_ONLY` 与 `PRODUCT_INVENTORY_SYNC`，并删除 `INBOUND` 累加模式。
- 删除“销售扣减、退货回补、销售修正版差额回算库存”的逻辑和测试。
- `InventoryMovement` 改为更准确的 `InventorySyncRecord`，记录同步前后差异但不伪装成业务出入库流水。
- 增加库存快照历史；当前库存只保存最新投影，也可从最新快照查询得到。
- 如果没有独立采购业务，删除进货批次页面与接口；供应商价格继续作为商品供货信息维护。
- 人工调整不能直接修改 POP 权威库存；如保留，只能形成待下次 POP 同步覆盖的临时值，首版建议删除。
- 库存 Agent 使用最新 POP 快照、最后同步时间、负库存和同步差异进行分析。

## 9. 接口调整建议

| 接口 | 调整 |
|---|---|
| `POST /api/v1/imports/uploads` | 上传商品资料或每日销售文件，绑定门店与资料/营业日期，返回真实表头和映射建议 |
| `POST /api/v1/imports/{batchId}/preview` | 确认本批字段对应关系并预检商品/销售变更；重复条码多值展示最后非空行取值，不因差异阻断 |
| `POST /api/v1/imports/{batchId}/commit` | 原子提交预检计划和库存快照，不执行销售数量加减库存 |
| `GET /api/v1/admin/inventory/stores/{storeId}` | 返回 `quantity, source=POP, lastSyncedAt, sourceBatchId` |
| `GET /api/v1/admin/inventory/summary` | 汇总各门店最新 POP 库存 |
| `GET /api/v1/admin/inventory/snapshots` | 新增快照历史查询，支持门店、商品和时间范围筛选 |
| 进货批次、库存人工调整接口 | 首版删除，除非后续确认本系统还要独立维护采购或人工库存 |

## 10. 验收场景

- 首次商品导入后，最新已知库存等于商品文件中的 POP 库存。
- 再次导入商品资料后，文件中出现商品的旧库存被最新 POP 库存覆盖，不做差额累加。
- 已有商品主档时，可通过小批次同步 POP 中已有但尚未进入本系统的商品；该批次不会影响其他既有商品。
- 再次导入已有条码时，空字段保留系统旧值，有效非空字段覆盖；空库存不写零，新商品必填字段为空时整批阻断。
- 每日销售导入后，销售事实更新；文件中出现商品的库存等于 POP 库存列，不执行销量扣减。
- 每日销售文件中的零销量行不创建销售事实，也不更新当前进价、售价或库存；即使销售收入非 0 也同样舍弃。
- 负销量只作为销售退货事实，不自动增加库存。
- 修正版销售数量变化不会加减库存；该批 POP 库存观察值仍按提交顺序覆盖当前库存。
- 重复供应商行只形成一个库存观察值；存在多个非空值时取 Excel 原始行号最后一个并展示非阻断提示。
- 文件缺少某商品时不把该商品库存自动置零，并保留其最后同步时间。
- 后成功提交的 POP 批次覆盖此前当前库存，即使其资料日期或营业日期更旧。
- 商品资料未选择资料日期时不能进入预检；资料日期只用于追溯，不参与覆盖优先级。
- 负库存正常保存并生成告警。
- 普通用户不能通过参数更新或查看其他门店库存，但可以查看所属门店库存。

## 11. 已确认边界

- POP 每日销售汇总只包含门店当日销售商品，属于部分库存快照。
- 未出现商品保留最后一次已知库存，不自动置零。
- 商品资料表也包含 POP 最新库存，可用于初始化和周期性刷新未销售商品。
- POP 商品资料的可导出范围是单门店全部商品，包含零库存和已停用商品。
- POP 中的商品和库存数据本身是完整的；分批导入仅描述新系统的同步进度，不描述 POP 数据完整性或实体入库状态。
- 系统允许商品资料分多次导入；每批只覆盖其中出现的条码，批次缺少某商品不属于异常，也不清零、不停用或阻断。
- 每日销售表仍是部分快照，只覆盖当日销售商品。
- 每日销售表中销量为 0 的行整行舍弃，只有过滤后的非零销量行才属于可提交的部分销售与库存快照。
