# 多 Agent 协作销售分析系统实施计划（评审稿）

> 文档状态：DRAFT。用户确认并改为 APPROVED 前，禁止新增业务代码、数据库迁移和功能页面。

## 1. 项目目标

建设一套内部销售分析系统：管理员导入 POP 商品资料和每日销售汇总，管理门店商品与库存，查看销售、毛利及冷热商品分析，并通过固定多 Agent 工作流获得分析报告；普通用户可以查看所属门店的非敏感商品资料及最新已知库存，并可为所属门店导入每日销售汇总，但不能查询销售、成本、利润等经营数据。

## 2. 首版范围

### 包含

- 固定管理员、普通用户两类角色；管理员不绑定门店并可创建两类账户，普通用户唯一绑定一个启用门店，一个门店可以绑定多个普通用户。
- 用户不设置启用/停用状态；管理员可删除普通用户，也可在系统仍保留其他管理员时注销自己或其他管理员。删除或注销立即失去登录能力、全部会话失效且不可恢复，原用户名永久保留，历史身份继续可追溯。
- 门店、仓库与货位信息；仓库只表示位置，不保存库存。
- 全局商品档案、门店独立库存、门店库存汇总。
- `.xls/.xlsx` 商品资料和每日销售汇总导入。
- 管理员和普通用户均可导入每日销售汇总；普通用户的门店由登录账号确定，导入前必须选择营业日期。
- POP 中的商品及库存数据完整；商品资料导入支持从 POP 分批同步到新系统，并可在后续周期性刷新 POP 库存，不提供进货累加库存模式。
- 每日销售汇总按 POP 库存直接覆盖文件中出现商品的门店库存，不以销量计算库存；支持负库存和数据陈旧告警。
- 销售、毛利、门店对比、商品排行、冷热商品分析。
- 管理员专用多 Agent 对话、SSE 进度、图表和历史报告。

### 不包含

- 用户注册、多租户、移动端、小程序。
- 仓库级库存、采购订单、仓库调拨、会员和收银。
- 微服务、消息队列、MinIO。Elasticsearch 属于首版核心组件，仅用于商品检索。
- 动态自主 Agent、自由 SQL、普通用户 AI。

## 4. 架构基线

- 后端：Java 17、Spring Boot 3.5.8、Spring AI 1.1.2、Spring AI Alibaba 1.1.2.2、MyBatis-Plus 3.5.17、Spring Security、Flyway、Apache POI。
- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus、ECharts、Axios。
- 开发基础设施：本地 MySQL、Redis、Elasticsearch；生产使用阿里云 RDS MySQL、Redis 和 Elasticsearch 服务。
- AI：阿里云百炼 Qwen；API Key 缺失时仅禁用 AI 模块，不影响其他功能。
- 模块：`security`、`organization`、`catalog`、`search`、`imports`、`inventory`、`sales`、`analytics`、`agent`、`audit`。
- MySQL 是商品权威数据源；Elasticsearch 只保存商品搜索索引。无消息队列条件下采用数据库同步任务表与后台重试，支持全量重建。
- Agent 只能调用应用内参数化分析服务，不接触数据库连接和任意 SQL 工具。

## 5. 数据模型确认节点

在提供真实脱敏样表前，只确认实体职责，不确定最终列和 SQL。

| 实体 | 职责 | 已确认规则 |
|---|---|---|
| User / Role | 登录、固定角色、门店绑定、账户删除/注销 | 用户名唯一且永久保留；管理员可创建两类账户且不绑定门店；普通用户唯一绑定启用门店；无启停状态；删除或注销不可恢复并保留最小历史身份；系统至少保留一个管理员 |
| Store | 销售与库存归属 | `ACTIVE/DISABLED`；停用不清理历史；仅已停用且无账号或业务引用的空门店可物理删除，禁止级联清理；编码规范化后在现存门店中唯一且不可修改，删空店后可复用；名称可重复 |
| Product | 全局商品档案 | 条形码业务唯一；管理员可受控修改，内部商品 ID 和历史关系不变；只保存一个当前有效分类 |
| StoreProduct | 门店商品状态、当前售价与最新已知库存 | 门店 + 商品唯一；售价和库存只由 POP 导入覆盖，并保存来源日期、来源批次和最后同步时间 |
| Supplier | POP 导入形成的商品来源信息 | 仅用于展示货品来源；不设启停状态，不提供人工维护，新的供应商名称由导入直接写入 |
| Category | 全系统共享、最多 5 级的商品分类 | 根分类为第 1 级；仅叶子分类可关联商品；POP 类别以品类编码全局唯一匹配；人工父级无业务编码；两种角色均可创建和调整父级，仅管理员可重命名、启用或停用 |
| StoreProductSupplier | 门店商品唯一的当前供货来源和当前进价 | 记录包含门店 + 商品 + 当前供应商，同时约束每个门店商品最多一条；无启停状态，只由 POP 导入替换；非空新供应商覆盖旧记录，商品未出现或供应商为空时保留当前记录 |
| Warehouse / Location | 存放位置 | 不保存库存数量 |
| ProductLocation | 商品多货位关联 | 商品 + 货位唯一 |
| ImportTemplate / ImportBatch | 映射、预检、幂等、审计 | 销售批次按门店 + 营业日期 + 类型 + 文件指纹防重复 |
| InventorySnapshot / InventorySyncRecord | POP 库存批次与覆盖记录 | 商品资料和销售表均按批次内条码局部覆盖；记录覆盖前后值、来源批次和时间 |
| DailySales | POP 每日销售快照 | 门店 + 日期 + 商品唯一 |
| ScoreConfig / ScoreResult | 冷热规则与快照 | 权重合计 100% |
| Conversation / AgentRun | 对话、步骤、报告、图表 | 仅管理员访问 |

G1 必须产出：完整 ER 图、逐字段数据字典、两类 Excel 映射表、索引与外键清单、建表 SQL 评审稿。用户确认后才创建 Flyway `V1`。

- 页面：静态字段映射评审原型，不连接数据库。
- 接口：无正式业务接口。
- 完成条件：G1 通过，无未决核心字段。

### P2：工程骨架

- 后端：配置分层、统一响应、异常、分页、OpenAPI、健康检查；按 G1 创建最小 `V1`。
- 接口：API-001 `GET /actuator/health`；API-002 `GET /api/v1/system/info`。
- 前端：布局、路由、请求封装、全局错误、403/404、系统状态页。
- 验收：浏览器显示真实后端健康状态；Java 后端、MySQL、Redis 任一核心项异常时 API-001 返回 `DOWN`，Elasticsearch 或 AI 异常不改变整体健康状态；后端启动测试和前端构建通过。

### P3：登录、用户与门店

- 接口：API-009～026，涵盖 CSRF 初始化、登录、退出、当前用户、两类账户创建、个人资料、角色/门店修改、普通用户删除、管理员注销、管理员重置密码，以及门店查询、维护、启停和受限物理删除。
- 契约：用户与门店列表使用 `PageResult`，页码从 1 开始、默认每页 20、最多 100；创建返回 201，更新返回 200，删除和密码重置返回 204；PUT 通过请求体版本、DELETE 通过 `If-Match` 执行乐观锁，重复删除重试不重复审计。
- 边界与安全：M02 统一执行角色、账号门店绑定、最后管理员和门店生命周期不变量；M01 提供会话撤销，M03～M07 等模块通过稳定引用探针参与门店删除检查，M10 消费脱敏审计。引用检查不完整时删除失败；API-019 只操作当前认证主体；所有写接口执行 CSRF/Origin 校验和字段白名单。
- 页面：登录、用户列表/详情、我的资料、门店列表/详情和角色菜单；管理员和普通用户均可编辑本人姓名、性别、手工年龄和入职日期，但不能自助改密；用户管理不提供启停操作，按角色显示“删除普通用户”“注销管理员”或管理员重置密码。门店删除只对已停用门店展示，后端返回 `STORE_IN_USE` 时明确提示只能停用且不提供级联清理。
- 权限：后端返回 `SYSTEM_READ`、`USER_CATALOG`、`CATEGORY_ORGANIZE`、`SALES_IMPORT`、`ADMIN` 五个稳定权限 code；前端静态菜单按 code 裁剪，后端仍独立执行权限和门店范围校验。
- 验收：管理员可创建管理员和普通用户并登录；两类用户可编辑本人姓名、性别、16～100 的手工年龄和不晚于当天的入职日期，不能通过个人资料修改用户名、角色、门店或密码；普通用户不能切店或访问未授权管理员接口，但可以进入所属门店的每日销售导入页；删除普通用户、注销管理员会立即撤销其全部会话且历史身份仍可追溯；最后一个管理员不能注销或转为普通用户；有关联用户的门店不能停用，停用门店的历史数据仍可查询；只有已停用且无任何账号或业务引用的空门店可物理删除，删除不级联清理数据；越权返回 403。
- 测试：领域单元测试覆盖固定角色、最后管理员、个人资料和门店生命周期；应用层测试替换会话撤销、门店引用和审计端口；接口与数据库测试覆盖权限、CSRF、DTO 白名单、唯一约束、乐观锁及并发删除；前端组件测试和真实 API Playwright 覆盖管理员主流程、普通用户本人资料、会话失效与越权。

### P4：商品与基础资料

- 接口：API-030 至 API-057，涵盖公开商品查询、管理员商品、门店商品供应来源只读查询、多级分类、仓库货位、商品货位和 ES 索引管理；不提供供应商、供应关系或进价的人工写接口。
- 条码格式：按字符串处理并保留前导零，只允许 1 至 64 位数字或英文字母；Excel 科学计数法导致的精度丢失不能自动修复，预检时按错误行阻断。
- 商品修改：API-035 允许管理员修改条形码；新条码必须通过格式和全局唯一校验，商品内部 ID、历史销售、门店商品、库存快照、供应商和货位关系不迁移也不重建。商品资料导入以当前条码作为匹配键，不承担条码修改；不建立旧条码别名或历史条码匹配机制。
- 商品单位：直接保存为自由文本，不建设单位字典及单位管理接口；API-034/API-035 允许管理员维护，API-030/API-031 向普通用户只读展示。
- 商品分类：分类树全系统共享，不绑定门店，最多 5 级且根分类计为第 1 级；商品只能直接关联叶子分类，任何分类不得同时直接关联商品并拥有子分类。普通用户和管理员均可创建根分类或父级分类，并可调整现有类别的父级归属。接口必须提供树查询、创建和移动父级能力，父级调整必须阻止自引用、循环引用、超深层级及在已有商品的分类下增加子分类。移动含子分类的节点时，必须保证移动后的整个子树都不超过第 5 级。
- 商品分类维护：商品只保存当前有效分类 `categoryId`。API-034/API-035 允许管理员在创建或编辑商品时指定一个启用的叶子分类；普通用户只能读取分类。手工调整商品分类不改变分类树，必须记录原分类、新分类、操作人和时间。后续商品资料和每日销售导入都不得覆盖已有商品的分类。
- 分类权限：普通用户不能重命名、启用或停用分类；这些全局维护操作仅管理员可执行。前端普通用户页面不显示相应按钮，后端接口仍必须独立校验并对越权请求返回 403。
- 分类停用：API-057 允许管理员停用已有商品直接关联的系统分类，不级联停用、移动或清空商品分类。已有商品保持原状态并继续可查询，分类路径显示停用标记；停用分类不得用于 API-034/API-035 新建或调整商品。POP 源端不会停用分类，因此导入不设计“新商品命中已停用 POP 分类”的阻断或自动处理分支。
- POP 分类导入：商品资料中的品类编码和品类名称只在条码首次进入本系统时用于初始化商品分类；文件没有父级链路，不能从文件推断或擅自生成父级。系统中首次出现的 POP 商品类别创建为根分类；已有类别按品类编码匹配，后续导入不得覆盖分类名称、状态或员工设置的父级。同一条码后续导入的品类即使变化，也不得修改已有商品的 `categoryId`，以首次导入后保存在系统中的当前分类为准；管理员仍可通过商品编辑修改该分类。若新商品需要关联的 POP 类别已有子分类，预检必须以“商品只能关联叶子分类”错误阻断整批提交。
- 分类标识：POP 商品类别使用品类编码作为全系统唯一且不可由页面修改的导入匹配键；人工创建的父级分类没有业务编码，创建页面只要求名称，树关系统一引用系统内部 ID。
- 供应商进价：每个门店商品只保留一个当前供应商，当前进价随“门店 + 商品 + 当前供应商”组合保存。管理员可按门店查看，普通用户只看到所属门店商品的当前供应商名称；供应商和供应关系均无启停状态、无人工维护接口。商品资料和每日销售汇总无需预建关系，同条码出现非空新供应商时替换旧供应商并只保留新记录；同一文件重复条码按 Excel 原始行号最后一行决定供应商及配套进价，商品未出现或供应商为空时保留当前供应商。最后成功提交的 POP 批次覆盖目标门店当前值且不得影响其他门店。不建设进价或供应关系历史，历史销售成本仍以每日销售事实的成本快照为准。供应商及报价变化不进入业务审计。
- 售价归属：当前售价属于门店商品，不属于全局商品主档；同一条码在不同门店可有不同当前售价。普通用户只读取所属门店售价，管理员可查看各门店售价但不能手工维护；历史销售中的售价继续作为当日事实快照保存。
- 当前进价、供应商来源、门店售价和库存只允许由 POP 商品资料或每日销售汇总成功提交后更新；管理员页面只读展示当前值及来源，不提供手工修改、关系启停或删除。
- 页面：普通商品目录展示所属门店商品的当前供应商名称、当前售价、最新已知库存和最后同步时间，商品关联停用分类时显示“分类已停用”；两种角色均可在分类树创建分类和调整父级，前端显示当前层级、状态和是否为叶子节点，在会超过 5 级或目标父分类已有商品时禁止提交，只有管理员页面显示分类重命名及启停操作；管理员商品编辑页通过仅展示启用叶子节点的分类选择器维护商品当前分类，同时只读展示各门店当前供应商及当前进价、售价、库存和来源批次，不提供供应商或供应关系维护按钮；另有基础资料页和货位关联页。
- 验收：前导零往返不丢失，1 位和 64 位数字/字母条码通过，空值、65 位、空格、符号和精度已丢失的科学计数法条码被拒绝；管理员可以从商品编辑页修改为未占用的合法条码，冲突条码被拒绝，修改后 ES 可按新条码检索且既有业务历史仍归属同一商品；普通用户页面无商品编辑入口，直接调用修改接口返回 403。普通用户只能得到所属门店售价、库存和当前供应商名称，响应不存在其他门店售价、其他门店库存、进价、销量、金额、成本、利润或毛利字段；当前进价、售价和库存均无人工编辑入口或接口，只能由 POP 导入更新，供应商及门店商品供应来源也无启停状态或人工维护接口；非空新供应商名称无需预建并替换本店商品旧供应商，同文件重复条码由最后一行供应商 B 覆盖 A，提交后只返回 B，商品未出现或供应商为空时保留原值；修改一家门店的当前值不影响另一家门店；同一商品在 A 店与 B 店可以保有不同当前供应商和进价；新商品首次进入系统时以 POP 类别初始化分类，新 POP 类别首次出现时位于根部，员工移动至父级后再次导入仍保留名称和父级，已有商品再次导入其他类别时 `categoryId` 保持不变，管理员可在系统内另行修改商品分类，且无需覆盖“停用 POP 分类”场景；可创建并查询第 5 级分类，创建第 6 级或移动后导致任一子孙超过第 5 级时，前端禁止提交且后端返回明确错误；商品关联叶子分类成功，关联非叶子分类、在已有商品的分类下创建或移入子分类、或新商品导入匹配到非叶子 POP 类别时均被拒绝且原数据不变；管理员可以把商品改至其他启用叶子分类并在审计中查看新旧分类，普通用户没有商品分类编辑入口且直接调用接口返回 403；普通用户可创建和移动分类，但重命名、启停按钮不可见且接口返回 403；索引暂时不可用时返回明确错误且不泄露敏感字段。
- 分类停用补充验收：管理员停用有关联商品的分类后，商品状态、当前分类和搜索可见性不变，普通商品页和管理员商品页均显示分类停用标记；该分类不出现在商品分类选择器中，API-034/API-035 直接指定时被拒绝；重新启用分类后可以再次选择，普通用户无启停按钮且调用 API-057 返回 403。

### P5：Excel 映射与预检

- 接口：API-060 至 API-075，涵盖映射模板、目标字段、上传解析、映射预检、批次、提交、放弃和错误下载；详细契约见 `docs/api/04-imports.md`。
- 状态：`UPLOADED → VALIDATING → READY → COMMITTED`；失败 `INVALID`，放弃 `DISCARDED`。
- 页面：管理员使用“文件、门店与日期 → 模板与映射 → 预检 → 提交”四步向导；首版只有【商品资料】和【每日销售汇总】两种模板，商品资料导入必选资料日期，每日销售导入必选营业日期。普通用户的每日销售向导固定所属门店。
- 权限：普通用户仅能执行 `DAILY_SALES`，不能执行商品资料或库存同步导入，也不能维护字段映射模板。
- 模板：普通用户可选择管理员已启用的每日销售映射模板；模板的新建、修改和停用仍仅限管理员。
- 字段取舍：商品资料中的“毛利率”不提供目标字段，不写入任何核心实体；每日销售中的“销售毛利率”作为销售事实快照保留，但同期销售收入、同期销售数量和同期销售毛利率不提供目标字段。自动映射或管理员映射均不能绕过目标字段白名单，舍弃列在预检中展示为忽略列。
- 验收：支持 `.xls/.xlsx`、列乱序、别名、前导零、重复键、多余列；商品资料毛利率和销售表三列同期值显示为忽略列，当期销售毛利率正确映射为历史快照；错误行阻断整批。

### P6：商品资料与 POP 库存同步

- 【商品资料】模板：按所选门店和资料日期 upsert 商品、门店商品供应商当前进价、门店售价及门店最新已知库存，不提供“不更新库存”的独立模式。
- 业务前提：POP 已有完整商品和库存数据；这里的“新增商品”仅指该商品尚未同步到本系统，不代表尚未进入 POP、尚未采购或尚未完成实体入库。
- POP 可导出单门店全部商品并包含零库存、已停用商品，但新系统允许拆成多份逐批同步；每批按条码 upsert，新系统中不存在的条码新增商品主档和门店商品关系，已有条码更新资料、该门店商品供应商当前进价、门店售价和该店库存。
- 商品资料导入前由管理员必选资料日期，代表该文件的 POP 导出数据日期；不从文件名、上传时间或提交时间推断。
- 商品资料中的“售价”映射为所选门店的当前售价，不写入全局商品主档；批次成功提交后直接覆盖，同时保存资料日期和来源批次用于追溯，同一商品在其他门店的售价不受影响。
- 商品资料中的“含税成本价”映射为目标门店对应商品供应商关系的当前进价；批次成功提交后直接覆盖，不比较资料日期，不能影响其他门店。
- 商品资料中的“库存数量”覆盖目标门店当前库存；同批多值取 Excel 最后一条非空值，跨批次以后成功提交者覆盖，资料日期只用于追溯。
- 商品资料中的“毛利率”始终舍弃，不写入商品主档、门店商品或门店商品供应商关系，也不用于覆盖或计算当前售价、当前进价。
- 已有条码按“非空覆盖”合并：文件字段为空时保留系统旧值，非空且校验通过时才覆盖；空值不表示清空。新商品缺少条码、名称等必填字段仍属于错误行，非空字段格式错误也不能因旧值存在而跳过校验。
- 不提供 `INBOUND` 累加和人工库存调整，避免产生第二套库存口径。
- 粒度：当前库存按“门店 + 商品”唯一；快照按“来源批次 + 门店 + 商品”唯一且不可变；同步记录按“一个已提交导入批次一条”保存执行摘要，避免与快照重复。
- 新鲜度：按最近成功应用当前库存投影的 `lastSyncedAt` 计算，全系统默认阈值 3 个自然日，严格超过 3 天才陈旧；任何日期的后续成功 POP 批次都刷新新鲜度，从未同步为 `UNKNOWN`。
- 告警：首版只生成负库存与陈旧库存站内告警；负库存在提交时即时判断，陈旧库存每天凌晨 `04:00 Asia/Shanghai` 扫描。管理员只能确认知悉，异常消失后由系统自动恢复。
- 接口：API-080 至 API-089，门店最新已知库存、总库汇总、批次级同步记录、商品级快照、新鲜度、告警和全局陈旧阈值配置。
- 页面：管理员商品库存、总库最新已知库存、快照历史、同步记录、新鲜度、陈旧/负库存告警和阈值设置。
- 验收：未选择资料日期时不能预检；已有商品主档基础上，可用小批次同步 POP 中已有但尚未进入本系统的商品；支持将商品资料拆成多批依次导入；已有商品空字段保留旧值、有效非空值覆盖、新商品必填字段缺失阻断；最后成功提交批次更新目标门店的供应商当前进价、本店售价和库存，即使资料日期较旧，其他门店同商品同供应商的进价不受影响；新商品以 POP 类别初始化分类，同一条码后续携带不同品类时仍保留系统当前分类，管理员可在系统内修改；门店隔离、同条码新增/更新、批次未出现商品保持不变、最后批次覆盖、汇总准确和事务失败整批回滚；普通用户能从商品目录看到本店最新库存但不能切换门店。

### P7：每日销售导入

- 业务键：门店 + 营业日期 + 商品。
- 营业日期由管理员或普通用户在上传预检前从页面选择，销售文件内不解析日期；一次文件只归属一个营业日期。
- 管理员选择目标门店；普通用户不选择也不能提交 `storeId`，后端强制使用账号绑定门店。
- POP 字段中的“当前机构”就是本次导入的目标门店，不允许将该字段解释为其他门店或全局机构。
- 先过滤“本期销售数量 = 0”的源行：整行舍弃，不创建销售事实，也不参与当前进价、门店售价、库存同步或同条码聚合；即使该行销售收入非 0 也同样舍弃。负销量不属于此规则，仍作为退货事实。
- 业务前提：每份每日销售文件在过滤零销量行后至少保留一条非零销量数据；“整份文件均为零销量”不纳入首版功能分支、错误码和验收范围。
- 同文件同条码的不同供应商行在零销量行过滤后按条码聚合销售事实；供应商及配套进价按 Excel 原始行号最后一行覆盖，提交后门店商品只保留该供应商。供应商不进入核心销售事实维度。
- 销售汇总只包含当日销售商品，属于 POP 部分库存快照；只覆盖文件中出现商品的门店库存，未出现商品保持原值。
- 销售数量不加减库存；修正版只覆盖销售事实，负销量只作为退货事实。库存按文件中的“选中机构库存数量/当前机构库存数量”直接覆盖。
- “当前机构售价”始终保存为该营业日期的销售快照；批次成功提交后同时覆盖该门店当前售价，不比较营业日期，同批多值取最后非空行，跨批次以后提交成功者胜出。
- “当前机构最后进价”始终保存为该营业日期的成本快照；批次成功提交后更新目标门店对应商品供应商关系的当前进价，唯一键为“门店 + 商品 + 供应商”，不比较营业日期且不能影响其他门店。
- 每日销售表中的“销售毛利率”按门店、营业日期和商品保存为历史事实快照，不使用商品资料毛利率或后续变更的售价、进价覆盖。
- 每日销售表中的同期销售收入、同期销售数量和同期销售毛利率全部舍弃，不写入销售事实，也不用于补齐历史比较结果。
- 较旧营业日期的补录仍按销售事实业务键新增或修正；其中 POP 进价、售价和库存作为最后成功提交批次的当前值直接覆盖，营业日期只用于追溯。
- 接口：复用 API-066 至 API-075；预检和批次详情增加零销量忽略数量及行级忽略原因，并展示营业日期、销售新增/修正/退货、库存/售价/进价覆盖、同批次重复值取最后非空行提示和来源日期追溯摘要。
- 页面：管理员与普通用户共用销售导入页，根据角色固定/选择门店；页面包含营业日期、文件上传、预检结果和确认提交。
- 数据隔离：普通用户可以查看所属门店全部用户创建的销售导入批次，但不能查看其他门店批次；敏感成本、毛利及经营明细不在普通用户响应中返回。
- 操作范围：普通用户只能提交或放弃本人创建且尚未提交的批次；管理员可处理全部门店批次。
- 验收：两种角色均可从页面完成销售导入；普通用户能看到所属门店其他用户创建的批次，但伪造 `storeId`、访问其他门店批次、操作他人批次或导入其他类型时返回 403；零销量行不产生销售事实且不更新当前进价、售价或库存，负销量仍保留为退货事实；当前值直接覆盖、缺失不清零、重复条码多值取最后非空行、较旧日期后提交仍覆盖当前进价/库存/售价、销售修正版、负库存告警和事务回滚测试通过。
- 销售事实长期保留，首版不设置自动删除或只保留最近一个月的规则；用户每次选择的主查询区间最多连续 31 个自然日。
- 同比、环比所需的历史对比区间由后端根据主查询区间自动计算和读取，不要求用户扩大主查询窗口，也不受“只能保留一个月”限制。

### P8：经营看板

- 接口：API-090 至 API-095，概览、趋势、门店对比、商品排行、毛利、异常。
- 页面：统一门店/日期筛选、指标卡、趋势、门店对比、排行、毛利和异常。
- 比较口径：同比取主查询区间向前推一个自然年的对应日期区间；环比取紧邻主查询区间之前、自然日数量相同的连续区间。全部从系统销售事实计算，不读取 POP 同期列；历史数据不足时返回“暂无可比数据”及缺失原因，不把缺失误报为增长率 0%。
- 验收：G4 通过；金额精度、退货、空周期、跨月、门店过滤、普通用户 403 测试通过。

### P9：冷热商品

- 默认权重：销量 35%、销售金额 30%、增长率 20%、动销天数 15%；合计 100%。
- 默认阈值：热门 80、冷门 30；结果保存配置快照。
- 接口：API-100 至 API-104，评分配置、运行和结果。
- 页面：评分配置、冷热列表、维度得分和解释。
- 验收：权重、相同极值、无上期、新商品、零销售和快照稳定性测试通过。

### P10：固定多 Agent

- 页面：会话、提问、Agent 时间线、流式答案、受控图表、历史报告。
- 验收：模型桩验证编排和失败；真实 Qwen 受控联调；普通用户 403。

### P11：审计、验收与上线

- 接口：API-120 至 API-122，审计日志、配置状态和运维状态。
- 审计定义：审计日志是关键业务操作的只读追踪记录，不是销售事实、库存快照或程序错误日志；记录操作人、时间、模块、动作、目标对象、门店、执行结果、请求追踪号及必要的变更摘要。
- 审计范围：记录登录及失败、账号权限、导入预检/提交/放弃、商品条码和商品所属分类修改、分类创建及父级调整、分类重命名与启停、库存同步与告警处理、分析配置与 Agent 操作；POP 形成的供应商及门店商品供应来源变化不纳入业务审计。
- 敏感保护：不记录密码、密码哈希、Cookie、会话标识、CSRF token、Redis 会话值、DashScope/API Key、数据库凭据或完整 Excel 内容；审计日志仅管理员可查，业务页面不提供编辑或删除能力。
- 页面：审计日志与系统状态。
- 验收：浏览器完成管理员“导入 → 库存 → 销售 → 冷热 → AI”闭环；关键操作可按操作人、模块、动作、门店、结果和时间检索，普通用户访问审计接口返回 403，敏感值不进入审计；普通用户只能查看所属门店公开商品字段及最新已知库存，并完成所属门店的每日销售导入，不能进入库存管理、经营数据与 AI 页面。
- 输出：部署、备份恢复、环境变量、阿里云切换和管理员操作手册。
